University of Bonn — agentic evaluation project

Can a model catch what a reviewer would?

SciFlawBench is a benchmark and harness for testing whether language model agents can find real flaws in scientific workflows — bad statistics, uncited claims, numbers that don't add up.

excerpt — the kind of thing we ask a model to catch

"…the black hole's mass was measured at M = 4.1 × 10⁶ M☉, consistent with the K-band luminosity relation [15,16]. This came from a single epoch of spectroscopy, confirming it as the most massive black hole in its host cluster…"

Table 1 lists M = 3.3 × 10⁶ M☉ for this source — the text and the data disagree.

[15,16] derive that relation for elliptical galaxies. This source isn't one — the citation doesn't support the claim.

One epoch of spectroscopy on one source can't rule out other massive black holes in the cluster.

§1 — what we're trying to do

Test scientific judgment, not recall

Most benchmarks ask a model to know things. This one asks a model to catch things — the kind of quiet errors a careful reviewer notices: a statistic that doesn't match its own table, a conclusion the cited work doesn't support, a claim built on too little data.

We built an agentic harness that runs models against a set of real and deliberately injected flaws, inside a proper research workflow rather than a multiple-choice quiz. The harness is built on smolagents, with a multiprocess architecture so the benchmark can run at scale.

§2 — our goal

A reliable, reusable measure — open to build on

We want a benchmark that's honest about what current models can and can't catch, that other researchers can run themselves, and that grows as more flaw types and papers are added to it. The harness, the task format, and the results are meant to be extended, not just published once and left alone.

§3 — the harness

Run the benchmark yourself

The harness handles dispatching agents against tasks, timing out runs, and scoring the result — you bring a model and a config file. It supports code-writing agents and tool-calling agents out of the box, with search tools (arXiv, Wikipedia, SerpAPI) available during a run.

§4 — how to contribute

Four steps to get involved

Read the project doc

Start with the write-up — it covers the benchmark design, the flaw categories we test for, and where things currently stand.

Clone and run the harness

Install it, point it at a model, and run the benchmark yourself. The README covers setup with pip or uv and how to write a task config.

Submit findings or new tasks

Found a flaw type we're missing, a bug in a run, or want to submit a candidate task? Tell us through the contribution form.

Get in touch

Questions, ideas, or want to collaborate more directly? Reach the team using the contact details below.

Numbered because contributing genuinely is a sequence here — read, run, submit, talk.
